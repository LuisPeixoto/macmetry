# Architecture

macmetry is a Cargo workspace of small crates, and one desktop app. The app, the command line and the MCP server are
three thin faces over the same core: a number means the same thing everywhere.

```
crates/
  macmetry-core    the data model, units, rates from counters, alert rules, exports. No platform code.
  macmetry-sys     the collectors for macOS, plus pure parsers tested with fixtures
  macmetry-store   the SQLite history
  macmetry-mcp     the MCP server
  macmetry-cli     the `macmetry` command
apps/desktop       Tauri 2 shell (src-tauri, Rust) and the Svelte 5 + TypeScript + Tailwind 4 interface (src)
docs/ tools/       these guides, and the scripts that need a real Mac
```

## macmetry-core

Everything that is not a system call. `Snapshot` is one reading of everything; every part a Mac may lack is an `Option`
or an empty list, which is how a desktop without a battery and a laptop share one type. `Metric` names each chartable
number with a stable key and reads it from a snapshot, so the history, the alerts and the MCP server never disagree
about what `cpu.total` means. Rates come from counters in one place (`rates.rs`), including counters that wrap, and
the alert engine is a pure state machine driven by each reading's own timestamp.

## macmetry-sys

The only crate that touches the operating system. Layers, bottom up:

1. `value` is a property-list-shaped tree. Parsers read it, and fixtures are loaded into it.
2. `sysctl`, `cf` (CoreFoundation) and `iokit` are the only places with raw FFI. Every `unsafe` block carries a
   `SAFETY` comment, which Clippy enforces.
3. One module per area (`cpu`, `memory`, `disk`, `network`, `gpu`, `battery`, `process`, `smc` and `sensors`,
   `ioreport`, `hid`). Each has a **pure parser** that takes text or a `Value` and returns structs, and a thin reader.
4. `sampler` runs every collector and assembles a `Snapshot`.

Design rules:

- **A collector that this Mac cannot support is left out**, not failed. It returns `SysError::Unsupported`, and the
  interface hides the card.
- **Private APIs are loaded with `dlopen`/`dlsym`.** If a macOS update removes one, only that card goes.
- **The SMC is read-only**: the write command does not exist in the code.
- **Real fixtures beat invented ones.** Platform output is captured once from a real Mac and committed under
  `tests/fixtures/`. The two battery fixtures are marked synthetic, because the development Mac has no battery, and are
  to be replaced with real captures.
- **Everything is bounded**: depth and size limits when converting CoreFoundation trees, caps on the number of
  processes, interfaces and registry entries.

## macmetry-store

SQLite with a `raw` table (one row a second, one column per metric, `NULL` where the Mac lacks it) and a `minutes`
table (average, lowest, highest and a count per metric). New metrics add columns automatically. `maintain` aggregates
completed minutes and prunes by retention. The command line and the MCP server open the file read-only. See
[History](history.md).

## The desktop app

`src-tauri` owns one **sampler thread**: every interval it measures, keeps a ten-minute live buffer, records the
history, evaluates the alerts, sends a notification when one fires, emits a `snapshot` event to the windows that are
visible, and updates the menu bar title. It reads processes only every other tick and only when a window is visible.
The interface is a thin view over those events and a few commands (`app_info`, `recent`, `query_history`,
`export_history`, `get_settings`, `set_settings`...). Commands return `Result<T, String>` with a sentence a person can
read. Native dialogs are opened only from Rust, and a file is written only after the person chooses where.

The interface talks to the outside through one layer, `api.ts`. In a plain browser it uses a **mock** of two Macs (an
Intel Mac Pro and an Apple silicon laptop), which is how the interface is designed and screenshotted without the app.

## Tests

- Unit tests next to the code, for parsers and logic, with fixtures.
- Integration tests: the real `macmetry` binary against a throwaway data folder, and the MCP server through a real
  client in memory and over a real pipe.
- Opt-in live tests (`#[ignore]`) that say what each kind of Mac **must** report. See `tools/live-tests.sh`.
- The tool reference, `docs/mcp-tools.md`, is generated by a test and fails when stale
  (`UPDATE_MCP_DOCS=1 cargo test -p macmetry-mcp --test docs` regenerates it).
- On the interface side, the metric list is compared with the Rust one key for key, and the English and Portuguese
  strings are checked to have the same keys, with every key used.
